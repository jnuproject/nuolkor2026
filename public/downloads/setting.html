opencode + NVIDIA 무료 LLM API 설정 가이드

새 노트북에서 opencode를 설치하고 NVIDIA(build.nvidia.com)의 무료 LLM API 키를 연결해 코딩 작업을 하는 방법을 순서대로 안내합니다.

위 탭으로 운영체제를 선택하면 해당 OS에 맞는 명령과 경로만 표시됩니다.

1. 사전 준비

  1. 터미널. 기본 Terminal.app으로 충분하며, WezTerm·Ghostty·Kitty 등을 써도 됩니다.
  2. Node.js 18+ (npm으로 설치할 경우에만 필요).
  3. NVIDIA 계정. 없으면 build.nvidia.com에서 가입.
  1. Windows Terminal + PowerShell 7 권장. 기본 PowerShell도 동작합니다.
  2. Node.js 18+ (npm으로 설치할 경우에만 필요).
  3. NVIDIA 계정. 없으면 build.nvidia.com에서 가입.

2. NVIDIA API 키 발급 (무료)

이 단계는 운영체제와 무관하게 동일합니다.

1 build.nvidia.com에 접속합니다.
2 우측 상단 Sign in → 계정 생성 또는 로그인.
3 사용하려는 모델 페이지로 이동 (예. nemotron-3-super-120b-a12b, Llama, Qwen, GLM 계열 등).
4 페이지의 Get API Key 버튼 클릭 → Generate API Key.
5 발급된 키(nvapi-... 형태)를 안전한 곳에 보관합니다. 키는 여러 모델에 공용으로 사용 가능합니다.
무료 tier에는 호출 수/속도 제한이 있습니다. build.nvidia.com의 각 모델 페이지에서 사용량 한도를 확인하세요.

3. opencode 설치

3-1. 설치 스크립트 (권장)

curl -fsSL https://opencode.ai/install | bash

3-2. Homebrew

brew install anomalyco/tap/opencode

3-3. npm

npm install -g opencode-ai
설치 후 opencode --version으로 확인합니다. command not found가 나오면 설치 스크립트가 안내한 PATH 줄을 ~/.zshrc에 추가하고 source ~/.zshrc를 실행하세요.

3-1. 네이티브 — npm

npm install -g opencode-ai
설치 후 opencode --version으로 확인합니다. opencode : 용어가 ... 인식되지 않습니다 오류가 나오면 터미널을 새로 열어 PATH를 다시 읽게 하세요.

4. NVIDIA API 키 연결

두 가지 방법 중 하나를 선택합니다. (A) 인터랙티브 /connect, (B) 환경 변수.

방법 A. /connect 명령 사용 (권장)

1 작업할 프로젝트 디렉토리로 이동 후 opencode 실행. 
cd /path/to/project
opencode
cd C:\path\to\project
opencode
2 opencode 안에서 /connect 입력. 
/connect
3 목록에서 NVIDIA 선택.
4 발급받은 NVIDIA API 키 입력 후 Enter. 
┌ API key
│
└ enter
5 /models 로 사용 가능한 NVIDIA 모델 목록 확인 후 사용할 모델 선택. 
/models
키는 ~/.local/share/opencode/auth.json에 저장됩니다. 노트북 분실 시 build.nvidia.com에서 키를 revoke하세요.
키는 사용자 프로필 아래 opencode 데이터 폴더(%LOCALAPPDATA%\opencode\)의 auth.json에 저장됩니다. 정확한 위치는 opencode 실행 시 표시되는 경로를 확인하세요. 노트북 분실 시 build.nvidia.com에서 키를 revoke하세요.

방법 B. 환경 변수 사용

셸 프로파일(~/.zshrc, bash를 쓰면 ~/.bashrc)에 다음을 추가합니다.

export NVIDIA_NIM_API_KEY=nvapi-여기에-본인-키

변경 사항을 적용한 뒤 opencode를 실행합니다.

source ~/.zshrc
opencode

확인은 echo $NVIDIA_NIM_API_KEY로 합니다.

PowerShell에서 사용자 환경 변수로 영구 등록합니다.

[System.Environment]::SetEnvironmentVariable(
  'NVIDIA_NIM_API_KEY', 'nvapi-여기에-본인-키', 'User')

또는 명령 프롬프트(cmd)에서.

setx NVIDIA_NIM_API_KEY "nvapi-여기에-본인-키"

등록 후 터미널을 완전히 닫았다가 새로 열어야 값이 반영됩니다. 확인은 다음과 같이 합니다.

echo $env:NVIDIA_NIM_API_KEY   # PowerShell
echo %NVIDIA_NIM_API_KEY%      # cmd
$env:NVIDIA_NIM_API_KEY = "..." 형태는 현재 세션에서만 유효합니다. 터미널을 닫으면 사라지므로 영구 설정에는 위의 SetEnvironmentVariable 또는 setx를 쓰세요.
환경 변수 이름은 6번에서 작성하는 provider.nvidia.env 값과 반드시 일치해야 합니다. 이 가이드는 NVIDIA_NIM_API_KEY로 통일합니다.

5. 프로젝트 초기화 필수 X

처음 작업하는 프로젝트라면 AGENTS.md를 생성해 opencode가 코드베이스를 파악하도록 합니다. 건너뛰어도 opencode는 정상 동작하며, 코드베이스 이해도를 높이기 위한 선택 단계입니다.

cd /path/to/project
opencode
/init
cd C:\path\to\project
opencode
/init

생성된 AGENTS.md는 git에 커밋하는 것을 권장합니다.

6. 기본 모델 지정 (전역 설정 권장)

매번 /models로 선택하지 않도록 기본 모델을 고정할 수 있습니다. 설정 파일은 두 곳에 둘 수 있습니다.

위치적용 범위용도
~/.config/opencode/opencode.json모든 프로젝트권장. 한 번만 설정
<프로젝트>/opencode.json해당 프로젝트만특정 프로젝트만 다른 모델을 쓸 때
위치적용 범위용도
%APPDATA%\opencode\opencode.json모든 프로젝트권장. 한 번만 설정
<프로젝트>\opencode.json해당 프로젝트만특정 프로젝트만 다른 모델을 쓸 때

둘 다 있으면 프로젝트 설정이 전역 설정을 덮어씁니다. 새 폴더를 만들 때마다 다시 설정하고 싶지 않다면 전역에만 작성하세요.

6-1. 전역 설정 파일 작성

mkdir -p ~/.config/opencode
$EDITOR ~/.config/opencode/opencode.json
# PowerShell
New-Item -ItemType Directory -Force "$env:APPDATA\opencode"
notepad "$env:APPDATA\opencode\opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "nvidia/z-ai/glm-5.2",
  "small_model": "nvidia/z-ai/glm-5.2",
  "provider": {
    "nvidia": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "NVIDIA NIM",
      "env": ["NVIDIA_NIM_API_KEY"],
      "options": {
        "baseURL": "https://integrate.api.nvidia.com/v1"
      },
      "whitelist": [
        "z-ai/glm-5.2",
        "deepseek-ai/deepseek-v4-pro",
        "deepseek-ai/deepseek-v4-flash"
      ],
      "models": {
        "z-ai/glm-5.2": {
          "name": "GLM 5.2 (NIM)",
          "tool_call": true,
          "reasoning": true,
          "limit": { "context": 202752, "output": 32768 }
        },
        "deepseek-ai/deepseek-v4-pro": {
          "name": "DeepSeek V4 Pro (NIM)",
          "tool_call": true,
          "reasoning": true,
          "limit": { "context": 262144, "output": 32768 }
        }
      }
    }
  }
}
메모장으로 저장할 때 인코딩을 UTF-8로 지정하세요. 기본값인 "UTF-8(BOM 포함)"이나 ANSI로 저장하면 JSON 파싱에 실패할 수 있습니다. 또 "다른 이름으로 저장" 시 파일 형식을 "모든 파일"로 바꾸지 않으면 opencode.json.txt로 저장됩니다.

6-2. 각 필드 설명

  • model — 메인 대화에 쓰는 기본 모델. <provider>/<model-id> 형식.
  • small_model — 대화 제목 생성, 요약 등 가벼운 작업용. 토큰을 아끼려면 nvidia/deepseek-ai/deepseek-v4-flash 같은 저렴한 모델로 분리하세요.
  • provider.nvidia — NIM은 OpenAI 호환 API이므로 @ai-sdk/openai-compatible로 직접 정의합니다.
  • env — 4-B에서 설정한 환경 변수 이름과 일치해야 합니다.
  • whitelist — /models 목록에 노출할 모델만 추립니다. 생략하면 전체가 뜹니다.
  • models — 커스텀 provider는 opencode가 모델 스펙을 모르므로 context/output 한도와 tool_call, reasoning 지원 여부를 직접 알려줘야 합니다.
모델 ID는 z-ai/glm-5.2처럼 슬래시를 포함합니다. 따라서 provider 접두사까지 붙인 최종 값은 nvidia/z-ai/glm-5.2로 슬래시가 두 개입니다. 정확한 ID는 build.nvidia.com의 모델 페이지 우측 코드 예제에서 확인하세요.

7. 주요 명령 요약

이 단계는 운영체제와 무관하게 동일합니다.

8. 문제 해결

  • 모델 목록에 NVIDIA가 안 보임: echo $NVIDIA_NIM_API_KEY로 환경 변수를 확인. 비어 있으면 source ~/.zshrc 후 재실행. 또는 /connect로 NVIDIA를 다시 연결.
  • opencode: command not found: 설치 경로가 PATH에 없습니다. ~/.zshrc에 export PATH="$HOME/.opencode/bin:$PATH"를 추가하고 source ~/.zshrc.
  • 모델을 못 찾음 (model not found): opencode.json의 model 값과 provider.nvidia.models의 키가 일치하는지 확인. nvidia/glm-5-2처럼 임의로 줄인 ID는 동작하지 않습니다.
  • 전역 설정이 적용되지 않음: 프로젝트 루트에 opencode.json이 있으면 전역 설정을 덮어씁니다. ls opencode.json으로 확인 후 불필요하면 삭제하세요.
  • 401 / 인증 오류: build.nvidia.com에서 키가 유효한지 확인. 만료/삭제된 키는 새로 발급.
  • 429 / Rate limit: 무료 tier 제한. 호출 간격을 늘리거나 다른 모델로 전환.
  • 에이전트 응답이 멈춤: provider 타임아웃을 늘립니다. 
    {
  "provider": { "nvidia": { "options": { "timeout": 600000 } } }
}
  • 모델 목록에 NVIDIA가 안 보임: echo $env:NVIDIA_NIM_API_KEY로 환경 변수를 확인. 비어 있으면 터미널을 새로 열어 재실행(setx는 기존 세션에 반영되지 않습니다). 또는 /connect로 NVIDIA를 다시 연결.
  • opencode 명령을 인식하지 못함: 터미널을 새로 열어 PATH를 다시 읽게 하세요. 그래도 안 되면 where.exe opencode로 설치 위치를 확인하고 해당 폴더를 사용자 Path 환경 변수에 추가.
  • 설정 파일이 안 읽힘: 탐색기에서 파일 확장명 표시를 켠 뒤 opencode.json.txt로 저장되지 않았는지 확인. 인코딩은 UTF-8(BOM 없음)이어야 합니다.
  • 모델을 못 찾음 (model not found): opencode.json의 model 값과 provider.nvidia.models의 키가 일치하는지 확인. nvidia/glm-5-2처럼 임의로 줄인 ID는 동작하지 않습니다.
  • 전역 설정이 적용되지 않음: 프로젝트 루트에 opencode.json이 있으면 전역 설정을 덮어씁니다. dir opencode.json으로 확인 후 불필요하면 삭제하세요.
  • 401 / 인증 오류: build.nvidia.com에서 키가 유효한지 확인. 만료/삭제된 키는 새로 발급.
  • 429 / Rate limit: 무료 tier 제한. 호출 간격을 늘리거나 다른 모델로 전환.
  • 에이전트 응답이 멈춤: provider 타임아웃을 늘립니다. 
    {
  "provider": { "nvidia": { "options": { "timeout": 600000 } } }
}
